# AIPubs GitHub Beginner Journey

The AIPubs Beginner Journey turns GitHub's software-development lifecycle into hands-on Open Flow missions. Learners produce real artifacts instead of completing a passive tutorial.

## Journey

```text
FIRST CONTACT → REPOSITORY → EXPLORE → GIT → BRANCH → ISSUE
→ BUILD → TEST → PULL REQUEST → SELF REVIEW → REVIEW FEEDBACK
→ MERGE → ACTIONS → RELEASE → DEPLOY → OPERATE → SECURITY
→ OPEN-SOURCE CONTRIBUTOR
```

## Learning contract

Every curriculum workflow should declare:

- prerequisites
- objective
- inputs
- outputs
- executable steps
- graduation criteria
- safety constraints

Graduation means an observable artifact or verified state exists. A workflow does not award completion merely because an AI says the lesson is complete.

## Progressive autonomy

The curriculum intentionally moves through OWF safety modes:

```text
observe → plan → guided → assisted
```

A read-only mission may inform a later action, but it never grants permission to perform that action. Any consequential transition remains subject to OWF's explicit safety gates.

## Composition

The curriculum is designed to compose with `OWF-011`. A user can start with a natural-language goal such as:

> I want to learn how to contribute to an open-source Python project.

The composer can resolve the appropriate journey stages, bind artifacts between them, and stop at explicit approval gates before consequential operations.

## Product principle

> AIPubs Open Flow is a free, open-source learning layer for GitHub that turns real software-development tasks into guided, executable learning experiences.

The beginner should be able to start with:

> **I don't know what I'm doing. Show me.**

And finish with a real repository, real commits, a real pull request, and eventually a real open-source contribution.
